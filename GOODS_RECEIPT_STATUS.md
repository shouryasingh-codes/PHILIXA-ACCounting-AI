# Goods received / bill pending — implementation status, 1 November 2026

## Working now

- Existing chat purchase can switch on “Bill nahi mila” / “bill nahi hai”.
- A durable, company/user-scoped receipt working copy lives in the existing
  PostgreSQL draft metadata, with a unique local tracking reference and audit
  events. No browser storage is authoritative; no migration is needed.
- Exact current supplier/item, matching base unit and positive confirmed
  quantity/rate are prerequisites. Existing invoice/source cannot silently
  switch modes. Old purchase previews are expired.
- Receipt date is explicit and separate from invoice date. Future dates are
  rejected. “Aaj mila” is an explicit user selection in the India timezone.
- Tax-exclusive, tax-inclusive and supplier-not-charging-GST are distinct
  user choices. Ambiguous “without GST” does not silently choose one.
- Pause/resume/reload retain the receipt and reference. Revisions and existing
  workspace/user permissions are enforced.
- Normal purchase preview rejects receipt-mode drafts, including attempts via
  the Bills API. A fake invoice, GST credit or duplicate stock purchase cannot
  be generated by this flow.

## Not implemented / not accepted yet

**This is receipt intake, not a completed Tally Receipt Note feature.** No
native voucher is posted, no stock is incremented and no liability/tax entry is
claimed. The chat explicitly says posting is unavailable.

The installed pinned MCP create_receipt_note contract has no item tracking-number
field and is already prerequisite-blocked. It must not be unlocked as if it
already supports this workflow. Operation-specific tracked Receipt Note
construction, dispatch/journal reconciliation, native verification and later
partial/full invoice linkage remain to be built and accepted. Linking must
prove stock changes only once. A 1-Apr–1-Nov-2026 read-only test-company voucher
query returned no Receipt Note fixture; no test voucher was created.

Actual user's five-bag transaction remains unposted; actual receipt date and
unambiguous rate-tax basis are still required.

Reference: https://help.tallysolutions.com/receipt-notes/
Tally documents receipt tracking numbers and their use in subsequent purchase
invoices. Documentation alone does not certify our connector implementation.
